# 校准与评估

## 概率 ≠ 准确率

模型返回 `billing: 0.91`，意思是"在这三个选项中，billing 占据了 91% 的概率质量"。

**这不等于模型有 91% 的概率是对的。**

要衡量实际准确率，需要标注数据做校准。

## 校准流程

### 1. 收集标注数据

准备 100-200 条已标注的 case（工单 + 正确答案）。

### 2. 运行打分

对每条 case 运行 `/v1/score`，记录模型返回的 top-1 答案和概率。

### 3. 计算实际准确率

```
实际准确率 = 正确预测数 / 总预测数
```

### 4. 概率 → 实际准确率映射

| 模型概率区间 | 实际准确率 | 含义 |
|-------------|----------|------|
| 0.90-1.00 | ? | 模型非常确信时，实际命中率是多少 |
| 0.70-0.89 | ? | 模型比较确信时 |
| 0.50-0.69 | ? | 模型不确定时 |
| 0.00-0.49 | ? | 模型几乎随机时 |

如果模型概率 0.91 对应的实际准确率是 95%，说明模型是校准良好的。如果只有 60%，说明模型过度自信，阈值需要调高。

### 5. 设定阈值

根据校准结果设定业务阈值：

```python
THRESHOLD_AUTO = 0.85   # 校准后：85% 以上概率 → 自动处理（实际准确率 ~95%）
THRESHOLD_REVIEW = 0.60 # 60-85% → 人工复核
# 60% 以下 → 直接拒绝或升级
```

## 局限性

### 本项目复现了什么

- Jev 式的推理路径（读取 logits → 受限 softmax → 返回分布）
- 基于 SGLang /v1/score 的实现
- 打分 vs 生成的延迟对比

### 本项目没有复现什么

- **训练/校准**：Jev 背后包含专门的训练和校准工作，单纯打分接口无法提供
- **RLCD（强化学习自定义蒸馏）**：Jev 可能使用 RLCD 优化决策质量
- **评估体系**：Jev 有完整的评估栈，本项目只提供基础基准测试
- **多 token 序列打分**：当前只支持单 token 标签，不支持多 token 短语打分

## 何时打分不够

- 候选答案无法事先枚举 → 用生成
- 需要解释理由 → 用生成
- 需要多步推理 → 用生成 + 思维链
- 候选答案 < 2 个 → 不需要打分也不需要生成，直接 if/else
